# Подготовка к переводу (утверждено 24.10.2026: код — Б, содержимое — В)

**Цель.** Подготовить модуль так, чтобы английскую версию можно было сделать переводом текстов, без переделки кода.
Сам перевод — потом и отдельно. Русская версия при подготовке не меняется ни на слово.

| Где | Сколько | Слов |
|---|---|---|
| Код `scripts/` — строки на русском | ~2 600 строк в 120 файлах | ~13 400 |
| Шаблоны `templates/` — текст и подсказки | ~330 мест | ~1 000 |

Самые «разговорчивые» файлы кода: Огранка (`stones.js`, `facet.js`), голоса Эха, Алтарь Памяти, Жильцы, карта,
Сделка луны.

## Что мешает перевести сейчас

1. **Нет каркаса.** Нет папки `lang`, нет ни одного вызова `game.i18n` (кроме 5 мест dnd5e). Каждая строка вписана
   в код как есть.
2. **Русские слова — это ещё и идентификаторы.** Теги (`'огонь'`, `'кровь'` — 54 места в коде), категории навыков
   (`'АНОМАЛИЯ'`), имена папок, по которым модуль ищет своё. Если перевести их вместе с подписями, сломаются
   синергии, Огранка, сохранённые миры. Идентификатор и подпись надо разделить: идентификатор остаётся русским
   навсегда (он в данных миров игроков), подпись — переводится.
3. **Содержимое — в компендиумах.** Навыки, правила, бестиарий, таблицы собираются из YAML в паки на одном языке.
   Foundry не умеет «перевести пак»: либо второй набор паков, либо модуль Babele.

## Как переводить код: два варианта

Foundry ищет перевод по ключу через точки (`GACHA.Trade.Title`), поэтому русский текст сам ключом быть не может —
в нём есть точки.

**А. Стандартные ключи Foundry.** `lang/ru.json`, `lang/en.json`: `"GACHA.Trade.Title": "Обмен"`. В коде —
`game.i18n.localize('GACHA.Trade.Title')`.
- Плюсы: так делают все модули; переводчики сообщества и сервисы (Weblate, Crowdin) это понимают; подхватывается
  настройками Foundry само.
- Минусы: из кода уходит русский текст — читать и править код станет тяжелее; ~2 900 ключей придумать и
  разнести; любая новая строка — правка в двух местах.

**Б. Текст — ключ (как gettext).** В коде остаётся русский текст, обёрнутый в помощник: `t('Обмен')`,
`t('Обмен {a} ⇄ {b}', { a, b })`. Скрипт собирает все `t(…)` в `lang/en.json`: `"Обмен": "Trade"`. Свой маленький
загрузчик словаря (точки в ключе ему не мешают); нет перевода — показывается русский.
- Плюсы: код читается как сейчас; обёртка — механическая правка без придумывания ключей; переводчик видит
  исходную фразу; новые строки ловит проверка «не обёрнуто».
- Минусы: не стандарт Foundry — внешним переводчикам нужен наш файл (это обычный JSON, но плоский); поправил
  русскую фразу — её перевод надо перенести (скрипт покажет пропавшие и новые).

**Предлагаю Б.** Модуль пишется и читается по-русски, и это главный язык. Переход на А возможен потом скриптом:
словарь «фраза → перевод» превращается в ключи автоматически.

## Как переводить содержимое: два варианта

**В. Второй набор паков при сборке.** Рядом с YAML — перевод: `src/i18n/en/<путь>.yaml` с теми же полями (имя,
описание, тексты событий). `npm run build` собирает и русские паки, и английские (`gacha-skills-en` и т. д.).
Модуль берёт пак по языку клиента — у нас паки берутся в немногих местах (`getSkillPack` и ещё ~6), это одна
функция. Мир хранит id навыка — id в обоих языках один, кристаллы и Память не ломаются.
- Плюсы: без зависимостей; всё под нашей сборкой и проверкой схемы; можно переводить по частям.
- Минусы: модуль вдвое тяжелее на паки (~1–2 МБ); игроки видят оба набора компендиумов (лишние можно скрыть).

**Г. Babele.** Отдельный модуль сообщества, переводит паки на лету по JSON-файлам.
- Плюсы: стандарт для переводов паков.
- Минусы: зависимость для англоязычных столов; наши навыки — не только текст: флаги, теги, активности
  тоже частично словами.

**Предлагаю В.**

## Что сделать сейчас (подготовка, без перевода)

1. **Каркас.** `scripts/core/i18n.js`: `t(текст, данные)` и помощник шаблонов `{{t "текст"}}`; загрузка
   `lang/<язык>.json`, если язык клиента не русский; без перевода — русский текст. `lang/en.json` — пустой.
2. **Идентификаторы отдельно от подписей.** Теги, категории, редкости, типы узлов: в коде — неизменные
   идентификаторы, подписи — через одну таблицу и `t()`. Поведение не меняется.
3. **Обёртка строк кода и шаблонов** в `t()` — по файлу, с проверкой в Foundry после каждой части. Порядок:
   интерфейс игрока (Терминал, карта, обмен, Алтарь) → карточки навыков → окна Мастера → сообщения.
4. **Инструменты** `tools/i18n/`:
   - `extract.mjs` — собирает все `t()` в `lang/en.json` (новые — пустыми, пропавшие — в отчёт);
   - `check.mjs` — строки на русском вне `t()` в коде и шаблонах (сначала отчёт, потом — проверка в прогоне);
   - отчёт покрытия: сколько переведено по разделам.
5. **Содержимое.** Сборка понимает `src/i18n/en/…` (пока пусто), паки с суффиксом языка, выбор пака по языку.
6. **Правило в CLAUDE.md:** новые строки — сразу через `t()`.

Объём подготовки: каркас и инструменты — 1 сессия; разделение идентификаторов — 1 сессия; обёртка ~2 900 строк —
3–4 сессии частями (механически, но с проверкой каждого окна); сборка паков по языку — 1 сессия. Перевод
40 000 слов — отдельная работа после.

## Сделано (24.10.2026)

- **Каркас:** `scripts/core/i18n.js` — `t(фраза, данные)`, помощник `{{t "фраза" имя=…}}`, словарь
  `i18n/<язык>.json` грузится на `i18nInit` для не русского клиента; названия и подсказки настроек модуля
  переводятся после загрузки словаря. Не `lang/`: Foundry раскладывает ключи по точкам.
- **Идентификаторы:** `scripts/core/ids.js` — теги и категории навыков, подписи `tagLabel`, `tagsLabel`,
  `categoryLabel` и помощники `{{tagLabel}}`, `{{categoryLabel}}`. Места показа тегов и категорий переведены
  на подписи: панель и прежнее окно Терминала, Огранка, Алтарь, кристалл, черновик добычи, добыча,
  фильтры компендиума, карточка кристалла; в данных (`data-tag`, фильтры, флаги) — прежние идентификаторы.
- **Инструменты:** `tools/i18n/extract.mjs` — словари из `t()` (новые — пустыми, готовые сохраняются);
  `tools/i18n/check.mjs` — что не обёрнуто (сводка по файлам, `--list файл`). На старте: ~2 500 строк в 155 файлах.
- **Проверка** `tools/foundry/i18n.mjs`; `i18n/` идёт в выпуск.

**Обёртка строк — сделана** (24.10.2026): весь интерфейс кода и шаблонов — через `t()` и `{{t}}`, `check.mjs` —
0 необёрнутых в 206 файлах; словарь `i18n/en.json` — 2 577 фраз (~13 800 слов), пустой.
- Словарь грузится синхронно при загрузке модуля (язык клиента — из `localStorage`, `core.language`), поэтому
  переводятся и таблицы на верхнем уровне модулей (тексты камней, подсказки), и названия настроек.
- Обёртка делалась инструментом на разборщике JS: не тронуты сравнения, ключи объектов, аргументы поиска
  (`getName`, `includes`, флаги), журнал разработчика, `Error`, идентификаторы; строка, которая где-то в коде
  сравнивается или ищется, не обёрнута нигде — создание и поиск не разойдутся. HTML в шаблонных строках кода —
  обёрнут текст между тегами (`${t('…')}`), разметка не в словаре.
- **Данные помечены** `// i18n: данные` — по ним модуль ищет и сравнивает: папки «Лабиринт: монстры» и
  «Лабиринт: герои», таблицы «Встречи», имена кристаллов «Кристалл: …» (их срезают регуляркой), имена навыков
  в коде (`Партейку?`, переименования), «Слои памяти» Пожирателя, «ПЗ» в глоссарии. На английском они остаются
  русскими — это внутренние имена; навыки и предметы получат английские имена из английских паков.

### Проверить, когда дойдёт до английского

- Имена эффектов и предметов, которые создаются переведёнными, а ищутся по началу имени или по полному имени —
  на русском совпадают как раньше, на английском — проверить прогоном на `en` (`tools/foundry/i18n.mjs`
  переключает язык; полный прогон на `en` — первым делом).
- Имена навыков в коде (данные) — заменить поиском по id навыка, когда появятся английские паки.
- Карточки чата пишутся на языке того, кто их создал (Мастер или игрок) — смешанный стол увидит карточки на
  языке автора; так устроен чат Foundry.
