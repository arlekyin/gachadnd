# Проверки в настоящей Foundry

Стенды (`tools/stand`) подменяют Foundry заглушкой. Эти проверки идут в настоящей Foundry с dnd5e:
Playwright заходит в тестовый мир, создаёт сцену, персонажа и врагов, кладёт навыки из компендиума
тем же путём, что и игра (`addSkillToMemory`, `setSkillEquipped`), и жмёт настоящие окна — окно
использования dnd5e, окно броска, панель модуля, HUD токена, карточки в чате.

## Подготовка

```
npm install
npx playwright install chromium
npm run build
```

Foundry запущена на `http://localhost:30000`. Если ни один мир не запущен, харнесс сам запускает
тестовый мир. Это работает, только когда у Foundry нет пароля администратора. Если запущен другой мир,
харнесс останавливается и ничего в нём не делает. В v14 мир запускается только со страницы настройки:
харнесс открывает её и нажимает «Запустить» у тестового мира.

Отдельная копия v14 с собственной папкой данных (`G:/foundry-v14/start-v14.bat`, порт 30001):

```bash
FOUNDRY_URL=http://localhost:30001 node tools/foundry/run.mjs
```

Пока мир запущен, `npm run build` не может пересобрать компендиумы: Foundry держит их файлы. Закройте мир
(«Вернуться к настройке» или `node tools/foundry/shutdown.mjs`) и соберите заново. Скрипты модуля (`scripts/`) подхватываются без сборки: каждый
запуск проверки заново загружает страницу.

Настройки окружения (по умолчанию):

| Переменная | По умолчанию |
|---|---|
| `FOUNDRY_URL` | `http://localhost:30000` |
| `FOUNDRY_WORLD` | `testrogalika` |
| `FOUNDRY_USER` | `Claude` (Мастер, без пароля) |
| `FOUNDRY_PASSWORD` | пусто |

## Запуск

Обычно — раннером: один браузер на весь прогон, перед каждой проверкой страница перезагружается, в конце —
песочница и сводка с временем каждой проверки. Полный прогон — около 7 минут.

```
node tools/foundry/run.mjs                       # все проверки и песочница
node tools/foundry/run.mjs light-auto blast-fire # только они и песочница
node tools/foundry/run.mjs --no-sandbox          # без песочницы
```

Каждую проверку можно запустить и отдельно — она откроет свой браузер:

Из корня репозитория. `--headed` открывает окно браузера, чтобы смотреть; `--slow` (или `--slow=1000`)
ещё и замедляет каждое действие — так видно, что нажимается.

| Команда | Что проверяет |
|---|---|
| `node tools/foundry/overheat.mjs` | Перегрев: трата заряда активностью dnd5e ловится в `preUpdateItem`, Перезарядка — окно цели и повторный `activity.use()`, первое заёмное без броска, к100 по шансу уровня (выдержал и сгорел), блок неудаляемого, Оверклокинг без окна и с ценой 2d6 ПЗ, короткий и долгий отдых |
| `node tools/foundry/aura.mjs` | Счётчик ауры: включение только в бою, позы через панель и окно броска dnd5e (помеха и −5 сохраняются после окна), КД −2 через `ac.bonus`, кнопка Мастера на карточке, пороги 2/4/5, автоматический спасбросок Мудрости со Сл, корона на HUD токена, «Не в этой арке», крит, натуральная 1, добивание, долг, конец боя |
| `node tools/foundry/light.mjs` | Навыки света: девять навыков в компендиуме (редкость, теги, заряды, отдых, урон), синергия «свет» проходит пороги 2/4/6 |
| `node tools/foundry/light-auto.mjs` | Ультрафиолет (тайные двери в радиусе), Призма (урон на 7 типов, сопротивление и иммунитет цели), Скорость света (ход вне очереди, свой ход пропущен, последний в очереди), Солнечная батарея (заряд на ярком свету, ночью — только у фонаря, 3 заряда → заряд навыка) |
| `node tools/foundry/light-zones.mjs` | Маяк (конус ставится мышью, свет туда же, ослепление врага, поворот на 90° каждый раунд, +1d4 союзнику, разбитый маяк гаснет), Диско-шар (6 цветных огней в 30 футах, карта Пятницы в начале хода и при заходе на пятно — через `moveToken` v13, новые пятна каждый раунд, уборка) |
| `node tools/foundry/light-big.mjs` | Рикошет (отражения от стен, прицел мышью, Esc без заряда, задетые — цели), Вспышка камеры (снимок 30 футов, проявка без заряда, занятая клетка), Спотлайт (темнота, свет на звезде, запрет атак по массовке, преимущество массовке, «Подыграть», перевод луча, угасание) |
| `node tools/foundry/blast-fire.mjs` | Огонь: компендиум (10 навыков `blast`) и третий порог «огня»; Это нормально (клетка мышью, распространение, стена, урон в начале хода и при заходе, временные ПЗ владельцу), Пол — это лава (стоял — горит, двигался или выше пола — нет), Раскалённый клинок (нагрев, урон огнём строкой, плавление, сброс конусом), Феникс (пепел, возрождение со вспышкой, растоптать пепел) |
| `node tools/foundry/blast-boom.mjs` | Взрывы: Горячая картошка (таймер шёпотом, передача кнопкой и запреты, взрыв с осколками), Ссссс… (взрыв, холостой с возвратом заряда), Красная бочка (клетки мышью, цепная реакция), Взрыв трупа (цепочка кнопкой), Утечка газа (отравление, рост, поджог огнём), Ох, да! (пролом стены, перенос, ничком) |
| `node tools/foundry/settings.mjs` | Настройки: в общем списке 5 общих и 5 кнопок подменю; подменю показывают и сохраняют свои поля; режим эффектов и общая громкость доходят до кода; шёпоты Запаха, строки атмосферы и шёпот Пульса слушаются переключателей. Возвращает значения мира как были |
| `node tools/foundry/sandbox.mjs` | **песочница для ручной проверки** — сцена «GD-песочница: навыки»: герои со всеми проверяемыми навыками (экипированы, без перегрузки), союзник, враги, стены-зеркала, тайные двери, фонарь, бой (не начат) и журнал «GD-песочница: как проверять». Запускается последней, после проверок |
| `node tools/foundry/shutdown.mjs` | закрыть тестовый мир перед `npm run build` (следующая проверка запустит его снова) |
| `node tools/foundry/inspect.mjs Имя…` | данные навыков из компендиума (флаги, активности) |
| `node tools/foundry/probe.mjs` | пользователь, модули, сцены, персонажи и компендиумы мира |

Каждая проверка заново создаёт документы с префиксом «GD-тест» (сцену, персонажей, бой) и удаляет
сообщения чата тестового мира. Документы «GD-песочница» проверки не трогают, но активной делают свою сцену —
поэтому песочница запускается после них. Снимки ложатся в `tools/foundry/out/`.

## Как устроено

- `harness.mjs`: запуск мира, вход, журнал ошибок страницы, `checker()` — проверки с итогом.
- `fixtures.mjs`: `window.gdt` в странице (`gdt.mod()` — модуль модуля, тот же экземпляр, что
  загрузила Foundry; `gdt.dice(20, 15, 12)` — подложить результаты костей; `gdt.chats()`, `gdt.warnings`,
  `gdt.windows()`), `scene()` — сцена с героем и врагами, `skills()` — навыки из компендиума.
- Окна других модулей (журналы изменений) закрываются перед кликами: они перекрывают HUD.
- `fixtures.mjs` умеет стены и тайные двери (`walls`), источники света (`lights`), ночь (`dark`), уровень героя
  (`hero.level`), сопротивления врага (`traits`), союзников (`disposition: 1`), бой (`combat()`) и использование
  навыка с ответами на окна (`use()`).
- `gdt.dice(грани, …)` заменяет очередь подложенных костей, `gdt.queue(грани, …)` дописывает в неё. Dice So Nice
  иногда забирает подложенную кость себе — там, где это возможно, проверка сверяется с карточкой в чате.
- `moduleErrors(log)` — ошибки модуля без чужих: fifthpendium падает на создании любого персонажа
  (`cleanName is not defined`), Foundry шумит при пересоздании сцены — ошибки считаются после подготовки.
- `gdt.settle()` — ожидание тишины: 250 мс без изменений документов мира. Им заменены паузы после смены
  хода и после использования навыка; там, где важны анимация или мышь, паузы остаются обычными.
- Перед пересозданием фикстуры ждут секунду: Combat Booster после использования навыка пишет флаг персонажу,
  и запись не должна прийти уже удалённому.
